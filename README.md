## 🚀 Project Structure

Inside of your Astro project, you'll see the following folders and files:

```text
/
├── public/
│   └── favicon.svg
├── src
│   ├── assets
│   │   └── astro.svg
│   ├── components
│   │   └── Welcome.astro
│   ├── layouts
│   │   └── Layout.astro
│   └── pages
│       └── index.astro
└── package.json
```

To learn more about the folder structure of an Astro project, refer to [our guide on project structure](https://docs.astro.build/en/basics/project-structure/).

## 🧞 Commands

All commands are run from the root of the project, from a terminal:

| Command                   | Action                                           |
| :------------------------ | :----------------------------------------------- |
| `npm install`             | Installs dependencies                            |
| `npm run dev`             | Starts local dev server at `localhost:4321`      |
| `npm run build`           | Build your production site to `./dist/`          |
| `npm run preview`         | Preview your build locally, before deploying     |
| `npm run astro ...`       | Run CLI commands like `astro add`, `astro check` |
| `npm run astro -- --help` | Get help using the Astro CLI                     |

## Production asset optimization

`npm run build` trims unused local CSS and minifies linked local CSS/JavaScript after Astro renders the pages. The output uses content-hashed filenames to avoid stale caches; editable source files remain unchanged. Run `npm run test:seo` and `npm run test:performance` after building, then use `npm run preview` to check the production result.

The CSS scan includes all rendered pages and the shared runtime. Classes generated by Bootstrap, Owl Carousel, and Magnific Popup are preserved in the safelist in `scripts/optimize-assets.mjs`. When adding dynamic UI, include its generated classes there and check the production preview. Carousel assets belong on About and Gallery; lightbox assets belong on Gallery; animation assets belong on pages using `ftco-animate`.

Two main stylesheets currently contain distinct overrides and retain their original cascade order. Duplicate footer imports of plugin/icon styles have been removed; both main stylesheets are pruned and minified during the build.
